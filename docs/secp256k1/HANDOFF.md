# secp256k1 in this fork: hand-off

State of the work on the optional secp256k1 curve, the decisions behind it and what is left.
Written 2026-10-20 at the end of phase 1, for a session that continues without the original
context. Keep the **Progress log** at the end up to date. The BP++ hand-off
(`docs/bppp/HANDOFF.md`) still holds for everything BP++.

## Goal

Every protocol of the crate (BP range and linear proofs, the inner-product argument, R1CS and
the circuit builder on both backends, all of BP++) over either ristretto255 (the default,
byte-identical to before) or secp256k1 behind the feature `secp256k1`, on k256. Compatible with
Elements / secp256k1-zkp where that is cheap: generator H, `generator_generate`, commitment
encodings, range proofs over Elements commitments. Not in scope: MACT for Elements.

## Interface (phase 1)

- `curve::Curve` (`Scalar`, `Point`, `Compressed`, `NAME`, `POINT_BYTES`, `compress`,
  `decompress`, `point_from_uniform`, `default_pedersen`, `msm_ct`, `msm_vt`, `msm_index`);
  `curve::Field` (an `ff::PrimeField` with `from_wide`, `to_bytes32`, `from_bytes32`,
  `batch_invert`); `curve::PointEncoding` (`as_bytes`, `from_slice`, `is_identity`).
- Types that hold points take `C: Curve = Ristretto`, types with scalars only `F: Field =
  Scalar` (`LinearCombination<F>`, `ConstraintSystem<F>`, `CircuitBuilder<F>`,
  `ArithmeticCircuit<F>`, ...).
- HashMap pattern: `BulletproofGens::new`, `PedersenGens::default`, `Verifier::new` exist for
  ristretto255 only; `for_curve` is the generic constructor. `Prover::new` infers the curve
  from the Pedersen generators. A call where nothing pins the curve (a standalone
  `X::from_bytes`, `LinearProof::create`) needs `::<Ristretto>`.
- Transcripts: `curve_domain_sep::<C>()` next to every protocol's domain separator; a no-op for
  ristretto255, `append_message(b"curve", NAME)` otherwise.
- Gadgets: `fn g<CS: CircuitBuilder>` is a ristretto255 gadget; `fn g<F: Field, CS:
  CircuitBuilder<F>>` runs on every curve (README, "Writing gadgets for both backends").

## The owner's rules

- Talk in Ukrainian or English, the language of the question. **Never write in Russian.**
- Commit finished, tested work without asking; **push and merge into `main` only when the
  owner asks.** End commit messages with the session's attribution lines.
- Ristretto proof bytes never change (golden tests, BP++ vectors regenerated by
  `ref/gen_vectors.py`, pins). Constant-time MSM for witness commitments, variable time only
  for public data. No constant-time requirement beyond that.
- The BP++ reference is secp256k1-zkp, not distributed-lab/bp-pp. Do not modify the
  secp256k1-zkp checkout.
- Method per phase: TDD per task (a failing test first), the full suites
  (`suite-all.sh` in the plan's workspace: four feature sets, benches build, vectors
  unchanged), a fresh review on the most capable model at the end of the phase, fixes with a
  failing test first.
